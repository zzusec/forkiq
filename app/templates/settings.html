仓库同步

检查上游和发现新仓库，是两件事。

分钟

每轮检查后等待此间隔，最短 0.25 分钟；可填 30、60 或 1440（每天）。仅检查已受管且未暂停的仓库。

每 60 分钟到期后在下一轮扫描已授权的新 fork；较长检查间隔会延后扫描，加入后即安排同步。关闭不影响已有仓库。

发现与同步有什么区别？

发现：把已有 fork 加入面板，不会创建 GitHub 仓库。扫描到期后在下一轮执行，加入的仓库在同一轮检查上游。使用「仅选定仓库」授权时，需先在 GitHub 授权新仓库。

同步：按上方间隔检查更新，发现更新后尝试同步。不想等自动扫描，可在仓库管理点「发现新 fork」或粘贴链接。

检查间隔不是完成时限。网络、限流或冲突可能延后同步；普通错误约 10 分钟后重试，权限和冲突需按提示处理。

异常删除保护

同步前先保留可疑变更，等待确认。

任一阈值被超过即拦截，比例以 fork 当前文件数为分母。空文件树始终拦截；无法完成检测也不更新。适用于镜像快进、强制对齐和手工合并，仓库详情可单独覆盖。

服务器备份固定开启：首次检查和每次更新前保存当前提交及其可达历史，每仓库保留最近 3 份不同版本。备份失败不更新，关闭删除保护也不能跳过备份。到仓库详情下载或回滚；回滚后保持暂停。

默认开启：超过 100 个或 50%。拦截后到仓库详情查看删除量及目标提交，必要时「确认并同步此次变更」。关闭保护有内容丢失风险。
